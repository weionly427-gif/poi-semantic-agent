# 优化计划

从旧版日志保留的规划，供后续优化参考。以下为当时记录，不代表已经实现；旧文件名对应的当前目录见根目录 README。

当前进度（2026-11-17）：距离硬上限已完成本地修复和离线验证，尚未部署。超过50公里目前返回范围说明，并非旧计划中的自动截断；其他条件、排序、复合距离仍需继续优化。历史阶段 A–E 是开发顺序，与测试用例 A–H 分组不同。

## 2026-11-17｜优化流程梳理（验证 → 修复 → 复测 → 评测）

### 现状理解

- 一期 agent：输入中文指令 → 硅基流动模型输出语义 JSON；`agent.mjs` 负责字段校验、上下文继承/重置、候选引用与反问；`home-search.mjs` 调高德做演示检索；`web.mjs` 提供网页与接口，`cli.mjs` 命令行，`agent.test.mjs` 离线单测。
- 程序只保证结构合法与状态传递，真实语义准确率靠真实样例持续评测；检索阶段目前只做高德综合排序，硬条件/软偏好尚未逐条核验。

### 阶段 A｜距离半径透传（当前主线，接续上一条）

- **要验证什么**　用户说"地标周围一公里内"，发给高德的 around 请求 `radius` 应为 1000 米；两公里应为 2000 米；只说"近一点"不编半径，回退默认值。
- **改动位置**　`home-search.mjs` 第 35 行固定 `radius:'3000'`；第 50 行写死"周边 3 公里"文案。
- **步骤**
  1. 先在 `spec.md` / `agent.mjs` 确认距离上限条件的 field 与 op（如 constraints 中 `field=distance`、`op=lte`、带 `value` 和 `unit`），避免把绕行时间、等待时间误当成搜索半径。
  2. 在 `home-search.mjs` 解析距离条件：公里 ×1000 换算成米；米直接使用；超出高德上限（50000 米）按上限截断；无明确数值时回退默认 3000。
  3. 模糊表达（"三五公里左右"等）按 spec 保留 raw、不取中间值；radius 取上限还是回退默认，在此记录决策结论。
  4. 周边文案改为按实际半径显示（如"周边 1 公里"），与实际请求一致。
- **复测**　分别输入"一公里内""两公里内""近一点"，抓 `/search` 请求参数核对 `radius`；再核对列表卡片的 `distance` 与半径是否匹配。
- **验收标准**　1 公里→1000、2 公里→2000、"近一点"→默认半径；文案与实际半径一致；不把 `detour_time` / `wait_time` 当成半径。

### 阶段 B｜检索后条件初筛

- **要验证什么**　硬条件（必须有停车场/洗手间/充电、现在营业、人均区间、评分门槛）在高德返回后逐条核验；软偏好（最好有、近一点、便宜点）不做硬过滤。
- **改动位置**　`home-search.mjs` 结果映射处（rating / cost / hours / parking / facilities 字段）。
- **步骤**
  1. 按 constraints 做本地初筛：设施类匹配 children / parking_type；营业中对照 `opentime_today`；人均对照 cost；评分对照 rating。
  2. 无法从高德字段核验的条件，保留在结果 message 中标注"尚未核验"，不误判为满足。
  3. preferences 只作为排序/提示依据，不参与过滤。
- **复测**　构造"必须有停车场的咖啡店""最好有洗手间的咖啡店"各跑一遍：前者无停车场应被筛掉，后者保留并标注偏好。
- **验收标准**　硬条件不漏放；软偏好不被当成硬排除；未核验条件有明确标注。

### 阶段 C｜补测试与评测集

- **要验证什么**　改动有离线测试兜底；spec 中的期望 JSON 可逐条回归。
- **步骤**
  1. `agent.test.mjs` 增加 home-search 用例：单位换算、模糊值回退、硬条件过滤正反例、无效候选引用。
  2. 按 `spec.md` P0 表整理"输入 → 期望 JSON 片段"对照表（10 条正例 + 1 条组合例），用 cli 或网页逐条跑，记录是否通过。
  3. 统计指标：语义准确率、歧义/反问率、平均解析耗时；失败样例回填到本日志。
- **验收标准**　`node --test agent.test.mjs` 全绿；P0 用例留有通过/失败记录。

### 阶段 D｜配置与健壮性

- **步骤**
  1. `.env.example` 补上 `AMAP_WEB_KEY`（`home-search.mjs` 已读取，但示例文件未列出）。
  2. 核对默认模型 `Qwen/Qwen3.5-35B-A3B` 在硅基流动是否可用，不可用时更换可用模型名。
  3. 复核超时（解析 30s、检索 7s）、高德报错 infocode、网络异常的提示文案是否可理解。
- **验收标准**　新机器按 README 复制 `.env` 即可跑通；报错信息不含堆栈、能指向原因。

### 阶段 E｜P1/P2 语义扩展（后排）

- 多类别 `any_of` 的 OR 检索；多目标 `tasks` 有序下发；候选引用失效处理；域外拒识；相对比较（"比第二家近"）。
- 每项先补 spec 用例与单测，再接检索层。

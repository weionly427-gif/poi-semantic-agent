# 一阶段 Agent · 对话上下文继承与重置规则

版本 v0.2 · 执行规则见 dialogue-policy.json，数字越小优先级越高。先判定任务关系，再确定是否反问。

## 基本约定

每次收到新的文字指令，都要判断它与当前任务的关系。唤醒或打开输入框只表示用户准备输入。开始新任务时，旧条件立即停止参与本轮解析；历史记录可继续展示。输入“重新开始对话”时重置活动任务。

## 判定表

| 情况 | 用户输入或事件 | 本轮使用哪些上下文 |
|---|---|---|
| 主动重置 | 明确说“重新开始对话” | 清空活动上下文。若同句带新需求，清空后解析新需求。 |
| 开始独立任务 | 前轮找咖啡店，本轮说“导航回家”或“帮我找个加油站” | 以本轮输入建立任务，旧类别、范围、停车条件、排序和候选均不继承。 |
| 补充条件 | “再近一点”“还得能停车” | 继承当前搜索目标和其他有效条件，更新对应偏好或追加要求。 |
| 替换或删除 | “换成咖啡店”“不用管停车了” | 只修改被点名的部分。保留适用于新目标的条件，移除仅属于旧目标的属性，如从充电站换成餐厅时的充电功率要求。 |
| 选择或追问候选 | “就第二家”“那家几点关门” | 使用用户当时看到的有效列表，分别解析动作和候选引用。列表缺失或已失效时，标记引用待确认。 |
| 回答澄清问题 | 上一轮问“咖啡店还是便利店”，用户答“后者” | 用上一轮问题及选项补全当前任务。若用户改说“导航回家”，结束旧问题并进入新任务。 |
| 取消当前搜索 | “算了，不找了” | 输出取消搜索意图，结束当前搜索并清除它的待答问题和活动候选。 |
| 指向不清 | “换一个”，既可能指下一家，也可能指换类别 | 暂存当前任务，标记两种解释，得到澄清后再更新。 |

## 更新时机

- **先判断关系，再合并字段。** “找个加油站”可以独立成立；“换成加油站”明确要求修改当前任务。同样的地点类别可以对应不同的继承方式。
- **候选随结果集更新。** 调整搜索条件后，旧列表停止作为新查询的默认引用。如果本句话本身引用旧候选，如“找个比第二家近的”，先用当时展示的列表解析参照，再更新任务。
- **失败允许重试。** 自动解析成功且 JSON 校验通过后，再提交新状态；超时或解析失败时保留最近一次有效状态。用户明确要求重置立即生效。
- **时间间隔。** 本稿不设固定超时阈值。若上层明确告知候选已过期，按引用失效处理。

## 最小验收

从“找附近必须能停车的咖啡店”开始，分别测试下列下一句。每个用例独立从同一初始状态开始。

| 下一句 | 期望 |
|---|---|
| “再近一点” | 咖啡店、附近、必须能停车均保留，增加距离偏好。 |
| “换成餐厅” | 类别改为餐厅，保留附近和停车要求。 |
| “帮我找个餐厅” | 新搜索只记录餐厅，不沿用上轮的附近和停车条件。 |
| “导航回家” | 目标为家，无咖啡店、附近和停车条件。 |
| “就第二家” | 若已展示列表则引用该列表第 2 项；若只有语义 JSON，则标记候选引用未解析。 |
| 输入“重新开始对话”，再输入“再近一点” | 缺少参照目标，标记待补充。 |

## 任务关系优先级

| 优先级 | 规则 |
|---|---|
| 10 | 明确重置 |
| 20 | 明确取消 |
| 30 | 更换搜索地点并重新给出目标，开始新任务；明确要求其他条件照旧时继续修改 |
| 40 | 完整独立请求或首轮请求，开始新任务 |
| 50 | 回答待澄清问题，补全待解决任务 |
| 60 | 补充、修改、删除条件或引用候选，继续当前任务 |
| 70 | 无法确定任务关系时，保留上下文并反问 |

## 反问优先级

依次处理硬条件冲突、缺少目标、候选引用不可用、任务关系不明、明确要求排名但缺少排序依据。每轮只问一个问题。未指定城市时默认本城市，地点实际定位交二阶段。普通推荐、近一点、便宜点、几家等表达可以直接解析。

## 输出与状态

每轮结果增加 dialogue.relation 与 dialogue.rule_id，标明新任务或继续任务及命中的规则。需要澄清时输出 intent=clarify、ready=false 和 follow_up，网页显示具体问题。程序把本轮待澄清语义保存在 dialogue.active_task 中，网页下一轮完整回传；用户回答后由模型补全原任务。

“中山公园附近的美食”后说“排名靠前的几家”，继续原任务并询问评分还是人气；随后说“按评分”，保留中山公园、美食并补上评分排序。“还是南京东路附近的美食吧”开始新任务，清除旧附加条件。
